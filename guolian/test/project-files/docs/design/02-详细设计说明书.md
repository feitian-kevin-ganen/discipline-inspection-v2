### 1.4 设计约定

1. **命名与表映射**：实体类名、表名严格遵循数据库设计 1.3 节对照表（OrgUnit→t_org_unit、AnswerSheet→t_answer_sheet、GradeRule→t_grade_rule + t_grade_rule_item 等）。试卷快照以 `t_paper_question`（固定卷题目快照）+ `t_answer_sheet.paper_snapshot`（一人一卷快照）实现，**不另设** `t_paper_snapshot` 表（以数据库设计为准）。
2. **枚举三态映射**：Java 枚举（API 字符串编码）↔ DB SMALLINT 字典值，统一由 `com.group.exam.common.enums` 下的枚举类承担双向转换，示例：`QuesType.SINGLE ↔ 1`、`SessionStatus.IN_PROGRESS ↔ 1`。API 层只出现字符串编码（SINGLE/MULTI/JUDGE/FILL/ESSAY、NOT_STARTED/IN_PROGRESS/ENDED/SCORED_PUBLISHED 等），DB 层只出现 SMALLINT，转换不得散落各业务代码。
3. **错误码**：一律使用 API 设计 2.5 节错误码（10xxx 通用/鉴权、20xxx 组织人员、30xxx 学习、40xxx 题库试卷、50xxx 考试、60xxx 统计），封装为 `ErrorCode` 枚举（见 2.3.2），禁止硬编码数字。
4. **接口路径**：管理端 `/api/v1/admin/**`、考生端 `/api/v1/app/**`（H5 与 PC 考生端共用），Controller 与 API 设计第 3 章 117 个接口一一对应。
5. **统一响应**：所有 Controller 返回 `R<T>`（`{code, message, data}`），HTTP 状态码约定遵循 API 设计 2.4。
6. **事务边界**：多表写操作在 Service 层 `@Transactional` 方法内完成；跨模块协作通过 Spring `ApplicationEvent`（同事务监听）解耦。
7. **审计字段**：实体的 `createBy/createTime/updateBy/updateTime` 由 MyBatis-Plus `MetaObjectHandler`（`AuditMetaHandler`）自动填充；`update_time` 同时由 DB 触发器 `f_touch_update_time()` 兜底。
8. **ID 生成**：统一使用数据库 BIGSERIAL 自增主键，实体 `id` 字段标注 `@TableId(type = IdType.AUTO)`。

#### 2.3.4 @DataScope 数据权限拦截器

**注解定义**：

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface DataScope {
    String orgPathAlias() default "";   // SQL 中带 org_path 字段的表别名，如 "ec"
    String userAlias() default "";      // 仅本人模式时的用户字段表别名
}
```

**实现机制**（MyBatis `Interceptor`，拦截 `StatementHandler.prepare`）：

```
1. 拦截到 SQL → 取当前方法上的 @DataScope（Mapper 方法标注）
2. 从 DataScopeHolder（ThreadLocal，由 LoginUserContextFilter 在请求进入时写入）取 LoginUser
3. 计算数据范围 dataScope（取用户所有角色中 dataScope 最小值——范围最大者优先，见 3.1.4）：
   ├─ dataScope=1 全部（SUPER_ADMIN）        → 不改写 SQL，直接放行
   ├─ dataScope=2 本节点及下级（各级管理员）  → JSqlParser 在 WHERE 末尾 AND 追加：
   │     {alias}.org_path LIKE '{loginUser.orgPath}%'
   │   （orgPath 为 t_org_user.org_path，如 '/1/12/'；LIKE 常量前缀走 varchar_pattern_ops 索引）
   └─ dataScope=3 仅本人（考生/阅卷）         → 追加 {userAlias}.user_id = {loginUser.userId}
4. orgPath 来自服务端登录上下文，前端传的任何 orgId 只做"范围收窄"校验：
   若请求 orgId 对应 path 不以 loginUser.orgPath 为前缀 → 抛 BizException(DATA_SCOPE_DENIED)
```

- 开发者未标 `@DataScope` 的管理端列表/统计 SQL 在代码评审中禁止合入（配套 ArchUnit 规则检查 `*Controller` 下管理端查询方法的 Mapper 调用链）。
- 对"目标行级"越权（如 PUT/DELETE 指定 id），拦截器无法处理，由 Service 层显式调用 `DataScopeChecker.checkOrgPath(targetOrgPath)` 校验（校验点清单见 8.1）。

#### 2.3.5 JWT 过滤器与登录上下文

```java
public class JwtTokenService {
    public String createAccessToken(LoginUser user);        // HS256，2h，载荷: sub=userId, jti, roles, orgPath
    public String createRefreshToken(Long userId);          // opaque，存 Redis auth:refresh:{token}，7 天
    public Jws<Claims> parse(String token);                 // 验签 + 过期校验
}

@Component @Order(2)
public class JwtAuthenticationFilter extends OncePerRequestFilter {
    // 白名单（/api/v1/auth/login、/refresh、/health）跳过
    // 1. 解析 Bearer token → Claims
    // 2. 黑名单校验：EXISTS auth:blacklist:{jti} → 401/10002
    // 3. 考生端答题态校验：请求头 X-Sheet-Token 与 Redis exam:online:{userId} 比对，
    //    不符 → R.fail(TOKEN_KICKED)（10010）
    // 4. 组装 LoginUser（userId/jobNo/orgId/orgPath/roles/permissions/dataScope）写入
    //    SecurityContext + DataScopeHolder（请求结束 clear）
}
```

权限表达式：Controller 方法级 `@PreAuthorize("hasAuthority('ques:item:edit')")`；权限点编码与 API 附录 A 一致（如 `org:*`、`mark:score:submit`），`*` 通配由自定义 `PermissionEvaluator` 支持。

#### 2.3.6 幂等注解 @Idempotent

```java
@Target(ElementType.METHOD)
public @interface Idempotent {
    String key();              // SpEL，如 "#req.clientBatchId"
    String prefix();           // Redis key 前缀，如 "exam:save:"
    long ttlSeconds() default 300;
}
```

`IdempotentAspect`（@Around）：`SET {prefix}{key} 1 NX EX ttl`，失败即重复请求 → 返回缓存的首次执行结果（首次执行成功后结果 JSON 写入同 key 覆盖占位值）；不存在 key 冲突约定时返回 `R.fail(DUPLICATE_SUBMIT)`。用于答案保存（clientBatchId）、学习心跳（eventId）、交卷（clientSubmitId）之外的管理端写接口防重点击。

#### 2.3.9 流水线引擎 PipelineEngine（Harness 落地核心）

```java
public interface PipelineStep<C extends PipelineContext> {
    String name();                          // Step 唯一名，YAML 声明引用
    StepResult execute(C context);          // 幂等实现要求：重复执行不产生副作用
    default boolean supports(C context) { return true; }   // 条件执行（如纯客观卷跳过阅卷等待）
}

public class StepResult {
    public enum Status { SUCCESS, SKIPPED, SUSPENDED, FAILED }
    private Status status;                  // SUSPENDED：流水线挂起等待外部事件（如阅卷完成）
    private String message;
}

@Component
public class PipelineEngine {
    // 启动时从 classpath: pipeline/*.yml 加载 PipelineDefinition（stage→steps 声明式编排）
    // Step Bean 按 name() 注册进 Map<String, PipelineStep>，YAML 只写名字即完成插拔
    public <C extends PipelineContext> PipelineRunResult run(String pipelineName, C context);
    // 执行语义：按声明顺序 Stage→Step；FAILED 记录断点（context.persistCheckpoint()）后可从断点重跑；
    // SUSPENDED 时保存上下文快照（Redis pipeline:ctx:{bizId}），外部事件触发 resume(pipelineName, bizId)
    public <C extends PipelineContext> PipelineRunResult resume(String pipelineName, String bizId);
}
```

判分流水线（gradePipeline）与统计流水线（statPipeline）均基于本引擎声明，见 3.5。

#### 3.1.2 认证流程（登录/刷新/JWT 生成校验）

```
login(jobNo, rawPwd, terminal, deviceId, ip):
  1. 限流：Redis INCR rate:login:{ip}:{jobNo} EX 60，>10 → RATE_LIMITED(10006)
  2. user = orgUserMapper.selectOne(job_no = ? AND deleted = 0)；不存在 → 记登录日志(失败) → UNAUTHORIZED(10002)
     （用户名错误与密码错误统一模糊提示"用户名或密码错误"，防账号枚举）
  3. account_status 校验：0 停用 → UNAUTHORIZED；2 锁定 → ACCOUNT_LOCKED(20007)
     所属单位 status=0（停用）→ 考生端登录拒绝（ORG-05 约定）
  4. BCrypt.matches(rawPwd, password_hash) 失败 →
     INCR auth:fail:{userId}；达 security.loginFailLock(默认5) → account_status=2 并 revokeAll → ACCOUNT_LOCKED
  5. 成功：清零失败计数；roles = roleService.listByUser；permissions = 角色 permissions JSONB 并集；
     dataScope = 所有角色 data_scope 最小值（1<2<3，范围最大优先）
  6. accessToken = jwtTokenService.createAccessToken(...)（载荷 sub/roles/orgPath/jti，2h）
     refreshToken = "rft_" + UUID，SET auth:refresh:{token} = userId EX 7d
  7. 更新 last_login_time/last_login_ip；写 t_sys_login_log(success)
  8. mustChangePassword = (account_status == 3 待修改初始密码)

refresh(refreshToken): GET auth:refresh:{token} → 失效抛 UNAUTHORIZED；轮换签发新双 token，
  旧 refreshToken 立即 DEL（旧 accessToken 剩余有效期短，不加黑名单）

logout(userId, jti): DEL auth:refresh:*（按 userId 索引键 auth:refresh_uid:{userId}）；
  SET auth:blacklist:{jti} 1 EX（剩余有效期）
```

#### 3.1.3 组织树维护（物化路径生成与变更算法）

**path 生成**（create）：

```
@Transactional create(req):
  1. parent = getById(req.parentId)；不存在 → PARENT_ORG_NOT_FOUND(20003)；parent.status=0 → 禁止挂新节点
  2. parent.path 前缀校验：parent.path 必须以 loginUser.orgPath 开头（否则 DATA_SCOPE_DENIED）
  3. level = parent.level + 1；> 6 告警（DB CHECK 上限 10）；unit_code 唯一冲突 → ORG_CODE_EXISTS(20002)
  4. INSERT（path 暂存占位）→ 取回自增 id → UPDATE path = parent.path + id + '/'
     （两步写避免序列先取值的耦合；同事务内完成）
```

**归属变更（moveParent，ORG-07 合并/迁移）**：

```
@Transactional moveParent(orgId, newParentId):
  1. 防环校验：newParent.path 不得以 node.path 为前缀（目标上级不能是自身后代）→ 10001
  2. 角色校验：仅 HQ_ADMIN/SUPER_ADMIN（@PreAuthorize），且 node 与新父均在数据权限内
  3. 事务内级联重算（核心 SQL，一次 UPDATE 完成整棵子树）：
     UPDATE t_org_unit
       SET path  = :newParentPath || substring(path from char_length(:oldPath) + 1),
           level = level + (:newParentLevel - :oldLevel)
     WHERE path LIKE :oldPath || '%' AND deleted = 0;
     其中 oldPath = node.path（变更前），newParentPath = 新父 path
  4. 同步刷新在职人员冗余路径（同学务）：
     UPDATE t_org_user SET org_path = :newParentPath || substring(org_path from ...)
     WHERE org_path LIKE :oldPath || '%' AND deleted = 0;
  5. 历史业务数据（t_answer_sheet / t_exam_candidate / t_learn_record 的 org_path 快照列）一律不回刷
  6. 失效受影响管理员的登录态（数据权限随 path 变化）：按子树内 userId 批量 revokeAll
  7. @AuditLog(module="ORG", operation="调整单位归属", logType=2)
```

**删除**：前置校验 `NOT EXISTS(子节点 deleted=0) AND NOT EXISTS(在职人员)` → 否则 ORG_HAS_CHILDREN(20004)；通过后物理删除（单位编码不复用，唯一索引含历史）。

**path 校对兜底**：`OrgPathCheckJob` 每日凌晨递归重建全树 path 与现值比对，不一致告警并修复（应对并发调整产生的极端不一致，见 6.1）。

#### 3.1.4 人员与角色权限

- **SecurityConfig**：`SecurityFilterChain` 配置——白名单 `/api/v1/auth/login`、`/api/v1/auth/refresh`、`/api/v1/health`、`/v3/api-docs/**`；`/api/v1/admin/**` 要求任一管理角色（SUPER_ADMIN/HQ_ADMIN/L2_ADMIN/SUB_ADMIN/MARKER）；`/api/v1/app/**` 要求 EXAMINEE；其余 authenticated。过滤器链：`RateLimitFilter(1) → JwtAuthenticationFilter(2) → SecurityExceptionFilter`。会话管理 STATELESS，关闭 CSRF（JWT 在 Header，天然免疫）。

  3. `INSERT_ONLY` 模式重复工号记失败行；`UPSERT` 模式按工号 `ON CONFLICT (job_no) DO UPDATE`；

#### 3.2.2 HeartBeatService 心跳处理详细设计（FR-LEARN-03，LEARN-04）

入参 `HeartbeatReq{materialId, eventId, positionSec?, pageNo?, readPages[]?, deltaSec}`。

```
heartbeat(userId, req):
  1. 幂等去重：SET learn:hb:idem:{eventId} 1 NX EX 86400；已存在 → 直接返回当前进度（code=0）
  2. 资料校验：存在且 PUBLISHED 且 LearnScopeChecker.visible → 否则 30001/30002
  3. 互斥会话（同一用户同一时刻仅一个学习会话计时）：
     cur = GET learn:session:{userId}            // value = materialId
     若 cur != null && cur != req.materialId     // 换资料：旧会话按超时截断规则收尾（见 4.2 时序）
     SET learn:session:{userId} = req.materialId EX 300（每次心跳续期 5min；5min 无心跳会话自动失效）
  4. 间隔校验与 delta 截断（防加速包/防挂机）：
     hb = Redis Hash learn:hb:{userId}:{materialId}（field: lastTs, accSec, anchor）
     gap = now - hb.lastTs
     ├─ gap < heartbeatSec*0.8（默认 15s 参数 learn.heartbeatSec）→ 视为异常高频，本次 deltaSec 不计
     ├─ gap ≤ heartbeatSec*1.5 → 计 min(deltaSec, heartbeatSec*1.5)（单端失真截断）
     └─ gap > heartbeatSec*1.5 → 只计 heartbeatSec（上一周期截断；页面失焦/暂停期间前端停发心跳，
        服务端按"间隔超阈值截断不计"收口；与概要设计 5.2 的 [20s,60s] 容差窗口同语义，
        具体上下限由 learn.heartbeatSec × 系数声明式配置）
     delta = min(req.deltaSec, 截断上限)；倍速播放由前端按实际播放秒数上报 deltaSec，服务端不再折算
  5. 累计与进度推进（单调不退）：
     accSec' = hb.accSec + delta
     progress' = max(当前进度, 计算进度)：
       文档：distinct(readPages)/page_count ×100（readPages 合并入 Redis Set learn:pages:{userId}:{materialId}）
       视频：min(positionSec, durationSec)/durationSec ×100（position 取 max，防回拖刷进度——
             有效时长已独立累计，进度只认最大到达点）
  6. 写回 Redis：HSET learn:hb:{userId}:{materialId} {lastTs, accSec}；HSET 进度锚点
  7. 异步批量落库（削峰）：提交 LearnRecordSyncEvent 至内存队列，
     SyncWorker 每 5s 批量 UPDATE t_learn_record（命中 uk_learn_record_um）：
       effective_duration_sec、progress、read_page、play_position_sec、last_heartbeat_time、last_learn_time
  8. 完成判定（FR-LEARN-05）：
     若 finish_status != 2 且 progress ≥ learn.completeThreshold(默认0.9)×100
        且 accSec ≥ duration_sec × learn.durationThreshold(默认0.8)：
       → finish_status=2, finish_time=now（落库），同时刷新 t_learn_task_user.complete_status
         （该用户含此资料且 required_duration_sec 满足的任务行 → 1 已完成 + complete_time）
  9. 返回 {progressPct, effectiveSec, status, serverTime}
```

**断点续学**（LEARN-02/05）：`breakpoint()` 读 `t_learn_record`（Redis 未落库部分以 `learn:hb` 为准合并）返回 `{progressPct, lastPosition, readPages[], effectiveSec, status}`；文档 `lastPosition=read_page`，视频 `lastPosition=play_position_sec`。

**会话关闭 Job**：`LearnSessionCloseJob`（每 1min）扫描 `learn:session:*` 过期用户 → 强制落库其 `learn:hb` 残留数据并 DEL（兜底 SyncWorker 未覆盖的尾巴）。

**学习完成判定 Job**：`LearnCompleteJudgeJob`（每 10min，ShedLock）扫描 `finish_status=1 AND last_heartbeat_time < now()-10min` 的记录，按第 8 步口径复核判定（兜底心跳进程内判定遗漏，如会话异常终止前已达阈值但未落库完成态）。

#### 3.3.2 题目 CRUD 与查重（FR-QUES-01~06）

- **题型结构**（与数据库设计 4.3.2 JSONB 约定一致，入库前由 `QuesItemAssembler` 从 API 请求结构转换）：
  - 单选/多选：`options=[{"key":"A","content":"..."}]`，`answer={"keys":["A"]}`；
  - 判断：固定 options T/F，`answer={"keys":["T"]}`；
  - 填空：`answer={"blanks":[["答案1","同义词1a"],["答案2"]]}`，`blank_config={"ignoreCase":true,"ignoreWidth":true,"unordered":false}`；
  - 简答：`answer={"reference":"...","points":["..."]}`。
- **stem_md5 生成**（`normalizeMd5`）：`Jsoup.parse(stemHtml).text()` 去 HTML → 去除全部空白字符 → 全角转半角 → 小写化 → MD5。新增/编辑/导入时计算写入 `stem_md5`。
- **查重**（QUES-12，QUES-06 保存时自动执行）：
  1. 精确：`SELECT id FROM t_ques_item WHERE stem_md5 = :md5 AND status != 3 AND deleted=0`（命中即 similarity=1.0）；
  2. 相似：取同题型启用/待审题目摘要（按 `idx_ques_item_type` 过滤后取最近 2000 条候选，缓存 Redis `ques:stems:{type}`，TTL 10min），逐条计算 `SimilarityUtils.jaccard(normalize(stem), normalize(candidate))`（字符 3-gram Jaccard 相似度），阈值 0.85（参数 `ques.dup.threshold`）取 TOP5；
  3. 结果作为 `dupHints` 提示返回（默认不阻断；参数 `ques.dup.block=true` 时抛 40002 且 data 携带疑似列表）。
- **导入**（QUES-10）：`.xlsx` 按题型分 sheet 解析（题型列映射 SINGLE/MULTI/JUDGE/FILL/ESSAY）；`.docx` 按约定标记段落解析（【题型】【题干】【选项】【答案】【解析】块）；校验项：题型可识别、选项 ≥2 且答案 ⊆ 选项 key、填空 blanks 非空、简答 reference 非空；逐行查重结果写入 failures 的 reason（"疑似重复"仅提示不阻断）；成功行初始状态按 `ques.auditRequired` 置 DRAFT(0)/PENDING_AUDIT(1)。
- **审核**（QUES-13）：ENABLE→2（启用）/REJECT→0（草稿）/DISABLE→3（停用）；仅 ENABLED(2) 可组卷（违反抛 40007）；写操作日志。
- **统计冗余**（FR-QUES-07）：判分完成后由 `QuesStatRefreshJob` 按 `t_answer_detail` 聚合批量刷新 `answer_count/right_count/right_rate`（判分主流程不写，防写放大）。

#### 3.3.3 随机抽题算法（FR-PAPER-02，PaperAssembleService.assemble）

策略来源：`t_paper.random_strategy`（JSONB，结构见数据库设计 4.4.1：`rules[].bankIds/withChildren/quesType/score/items[{difficulty,count}]` + `shuffleQues/shuffleOption`；场次创建时副本已固化到 `t_exam_session.paper_strategy_snapshot`，实际抽题以快照为准）。

```
assemble(paper, seedUserId):
  1. 解析策略 strategy = parse(paper.random_strategy)
  2. bankIds 展开：rule.withChildren=true 时，SELECT path FROM t_ques_bank WHERE id IN rule.bankIds
     → 前缀数组 bankPathPrefixes（如 {'/1/5/%'}）
  3. 逐条 rule × 每个 difficulty 档抽题（集合化一次 SQL，对应数据库设计 5.5 集合化版本）：
     - 候选集：t_ques_item JOIN t_ques_bank，
       WHERE status=2 AND deleted=0 AND ques_type=? AND difficulty=?
         AND b.path LIKE ANY(bankPathPrefixes)
     - row_number() OVER (PARTITION BY ques_type,difficulty ORDER BY random()) rn
     - 取 rn ≤ need_count
  4. 候选不足校验：任一档实抽数 < 需求数 → 抛 STRATEGY_ITEM_NOT_ENOUGH(40006)，
     message 标明缺口（"单选/难 需4道，候选仅2道"）；严禁降级乱抽
  5. 卷面校验：Σ(count × score) == paper.total_score，不等 → PAPER_SCORE_MISMATCH(40003)，整体回滚
  6. 去重：跨 rule 抽到同题 id 时以后抽规则重抽补齐（同卷同题只出现一次）
  7. 组装 PaperSnapshotDTO：
     {paperId, paperVersion, totalScore, passScore, multiJudgeRule, gradeRuleSnapshot,
      questions: [{quesId, quesType, score, seq, stem, options, answer(服务端留存), analysis,
                   blankConfig, optionOrderMap（乱序映射）}]}
  8. 乱序（策略 shuffleQues/shuffleOption 且场次未覆盖关闭时）：
     题序 Fisher-Yates 洗牌得 seq；选项序同样洗牌，重排展示 key（A/B/C...按新顺序重编），
     optionOrderMap 记录 {展示key→原始key} 固化进快照，判分时按映射还原比对标准答案
  9. 返回快照（调用方写入 t_answer_sheet.paper_snapshot）
```

- **same_paper=1（全考生同卷）**：首个考生进入时抽一次，快照缓存 Redis `exam:paper:shared:{sessionId}`（TTL=场次窗口）并持久化（复用预生成机制）；其余考生直接复用该快照副本（每人独立行但题目集相同）。
- **same_paper=0（一人一卷）**：每个考生进入时独立 assemble。
- **dryRun 试抽**：创建/预览随机卷（PAPER-02/07）时执行第 1~5 步（不落快照），提前暴露候选不足；预览样卷标注 `sample: true`。
- **固定卷**：`setQuestions` 全量替换 `t_paper_question`（含 `ques_snapshot` 题目快照：{stem,options,answer,analysis,difficulty}），校验总分一致（40003）与题目启用（40007）；固定卷的答卷快照直接从 `t_paper_question` 行组装（同样走第 7~8 步乱序）。

#### 3.3.4 等级规则与试卷封存（FR-PAPER-03/04/05）

- **区间校验**（GradeRuleService.saveRule / PaperService.saveGradeRules）：区间按 min_score 排序后逐段校验——首段 min=0、末段 max=full_score、相邻段边界衔接（`prev.max == next.min` 且开闭互补）、无重叠；不满足抛 GRADE_RANGE_INVALID(40005)。左闭右开、末段右闭（`lower_inclusive/upper_inclusive` 字段表达）。
- **封存**：场次创建（EXAM-02）关联试卷成功即 `PaperFacade.sealOnReferenced` → `paper_status: 1→2`；封存后 PAPER-04/06/10 一律抛 40004；演进路径为 PAPER-08 深拷贝（复制 `t_paper` 行 + `t_paper_question` 行 + 等级规则引用，`version+1`，新卷状态 0 EDITING）。
- **判分规则枚举**：`MultiScoreRule{ALL_OR_NOTHING(1) 全对得分, HALF_ON_MISS(2) 漏选得半分, NONE_ON_MISS(3) 错选/漏选均不得分}` ↔ `t_paper.multi_judge_rule`（1/2/3），快照时随 `paper_strategy_snapshot` 固化。

#### 3.4.2 场次状态机（FR-EXAM-04）

`SessionStatus`：NOT_STARTED(0) → IN_PROGRESS(1) → ENDED(2) → SCORED_PUBLISHED(3)。（API 另有 CANCELED，需 DB 扩展取值 4，见 8.4 不一致点说明；实现预留 `CANCELED(4)` 枚举。）

| 当前状态 | 触发事件 | 目标状态 | 执行动作 |
| --- | --- | --- | --- |
| NOT_STARTED | 到达 startTime（SessionStatusJob）/ 人工 START | IN_PROGRESS | 刷新 Redis `exam:session:{id}:meta`；写操作日志 |
| NOT_STARTED | 人工 CANCEL | CANCELED | 名单保留，通知考生（若已下发） |
| IN_PROGRESS | 到达 endTime（Job）/ 人工 END | ENDED | 触发未交卷答卷强制收卷（submit_type=3 批量）；ABSENT 标记延后由 AbsentMarkJob 处理 |
| ENDED | MARK-07 成绩发布 | SCORED_PUBLISHED | 写 score_publish_time；发布 `GradePublishedEvent` |
| 任意 | 非法流转 | — | 抛 SESSION_STATUS_INVALID(50007) |

人工流转入口 `transit()` 内部统一调 `SessionStateMachine.checkTransit` 校验，非法动作抛 50007；`SessionStatusJob` 每分钟扫描 `session_status=0 AND start_time<=now()` / `=1 AND end_time<=now()` 自动流转（ShedLock）。

#### 3.4.4 进入考试（TAKE-02，SheetService.enter）

```

  1. 加载场次 + Redis meta 缓存（exam:session:{examId}:meta，TTL 至 endTime）
  2. 校验链（任一不过即抛对应错误码）：
     a. 时间窗口：now < startTime 或 now > endTime → EXAM_NOT_IN_WINDOW(50001)
     b. 名单：t_exam_candidate(session_id,user_id,deleted=0) 不存在 → NOT_IN_CANDIDATES(50002)
     c. 迟到：now > startTime + late_limit_min 且 late_limit_min>0 → LATE_LIMIT_EXCEEDED(50008)
     d. 已有答卷：查 t_answer_sheet uk(session_id,user_id)
        ├─ submit_time IS NOT NULL → ALREADY_SUBMITTED(50003)（幂等返回首次交卷结果）
        └─ 存在且未交卷 → 走断线续考分支（resumeFrom=RESUME，见 3.4.7）
  3. 单终端控制（FR-TAKE-05，参数 exam.multiTerminal 默认 KICK_OLD）：
     old = GET exam:online:{userId}
     ├─ old 存在且 old.sessionId == examId：KICK_OLD → 旧 sheetToken 作废（旧端下请求返回 10010）；
     │   REJECT_NEW → 抛 OTHER_TERMINAL_ONLINE(50005)
     └─ old.sessionId != examId（在别的场次在考）→ 抛 50005
     新 sheetToken = "st_" + UUID；SET exam:online:{userId} = {sessionId}:{sheetToken} EX（窗口+2h）
  4. 生成答卷（新考分支）：
     deadline = min(enterTime + duration_min, endTime)（窗口截断；补考场次按补考窗口）
     snapshot = PaperSnapshotService.buildForCandidate(session, userId)：
       ├─ 固定卷 → 读 t_paper_question 快照行组装（按策略 shuffleQues/shuffleOption 乱序）
       ├─ 随机·同卷 → GET exam:paper:shared:{sessionId}，无则 PaperFacade.assembleSnapshot 生成并缓存
       └─ 随机·一人一卷 → PaperFacade.assembleSnapshot（候选不足抛 40006，考前 dryRun 已兜底）
     INSERT t_answer_sheet（candidate_id、考生与单位快照取自 t_exam_candidate 行、
       paper_snapshot=snapshot、start_time=now、server_deadline=deadline、
       session_token=sheetToken、terminal、user_agent、mark_status=0）
     批量 INSERT t_answer_detail 空行（每题一行：ques_id/ques_type/sort_no/ques_score，
       user_answer=NULL）——题序锚点 + sheetQuesId（detail.id）下发凭据
     SET exam:timer:{userId}:{sessionId} = deadlineEpoch EX（至 endTime+1h）
  5. 返回 {sheetId, serverTime, deadlineTime, remainingSec, resumeFrom=NEW, examRules{...}}
```

**校时**（TAKE-03 / TimerService.remainSec）：`remain = max(0, server_deadline - now)`；所有答题态接口响应均携带 `serverTime + remainingSec`，前端按 API 6.3 用 `performance.now()` 漂移校准。

#### 3.4.5 答案保存（TAKE-05，UPSERT 幂等 + clientBatchId 去重 + Redis 缓存与落库）

```

  1. 幂等去重：SET exam:idem:save:{clientBatchId} 1 NX EX 600；已存在 → 返回缓存的首次响应（code=0）
  2. 答卷校验：sheet 存在（50006）、属当前用户、session_token 匹配（AntiCheatService.assertTerminal，
     不符 → 10010）、未交卷（已交卷 → 50003）
  3. Redis 暂存（主写路径，P95≤500ms 的关键）：
     HSET exam:answer:{userId}:{sessionId}  field=sheetQuesId(detailId)  value=答案JSON
     （答案 JSON 结构：选择 {"keys":["A"]}、填空 {"blanks":[...]}、简答 {"text":"..."}，
      与 t_answer_detail.user_answer 列约定一致；写入前按 detailId 校验属于本答卷）
     同时 ZADD exam:dirty:{sessionId} {now} {sheetId}:{detailId}   // 脏数据登记（落库队列）
  4. 响应：{savedCount, serverTime, remainingSec, submitStatus}（submitStatus 反向通知强制收卷/到时交卷）
  5. 超时宽松窗口：now > server_deadline 且 ≤ deadline+30s 时仍接收保存（网络延迟容忍），
     但不改变已自动交卷的结果（submitStatus 返回 SUBMITTED）

AnswerFlushJob（每 5s，ShedLock）：
  1. ZRANGEBYSCORE exam:dirty:{activeSessionIds} 0 now-2s 取一批（≤2000 条）
  2. 逐条从 exam:answer:{userId}:{sessionId} HGET 答案值
  3. 批量 UPSERT（数据库设计 4.5.4 指定路径）：
     INSERT INTO t_answer_detail (sheet_id, session_id, user_id, ques_id, ques_type, sort_no,
                                   ques_score, user_answer, answer_time)
     VALUES (...) ON CONFLICT (sheet_id, ques_id)   -- uk_detail_sheet_ques
     DO UPDATE SET user_answer=EXCLUDED.user_answer, answer_time=now()
     （注意：冲突键为 (sheet_id, ques_id)，detailId 仅作 Redis field；UPSERT 由 sheet+ques 定位）
  4. 成功后 ZREM 已落库条目；失败保留待下轮重试（Redis 为主存，DB 为持久，NFR-02）
```

#### 3.4.6 倒计时与到时自动交卷（FR-TAKE-02）

  ```

   WHERE submit_time IS NULL AND sheet_status=1 AND server_deadline <= now() LIMIT 500;
  ```

#### 3.5.1 PipelineEngine 装配与 gradePipeline 声明

`PipelineEngine`（exam-common，见 2.3.9）启动时加载 `pipeline/grade-pipeline.yml`：

```yaml
pipeline: gradePipeline
trigger: ExamSubmittedEvent / AutoSubmitJob / 人工重判
stages:
  - stage: objectiveMarking            # Stage1 客观题判分
    steps: [snapshotLoadStep, choiceJudgeStep, multiChoiceStep, blankMatchStep]
  - stage: blankReview                 # Stage2 填空复核
    steps: [similarityCheckStep]
  - stage: subjectiveCompose           # Stage3 主观分合成
    steps: [subjectiveScoreStep, totalScoreStep]
  - stage: gradeLevel                  # Stage4 等级评定
    steps: [levelEvalStep, persistStep]
```

- **GradeContext**（Step 间传递，实现 `PipelineContext`）：`sheetId、sessionId、paperSnapshot、details(List<AnswerDetail>)、scoreMap(detailId→得分)、objectiveScore、subjectiveScore、totalScore、gradeCode/gradeName、reviewQueue(List<detailId>)、exceptionList、checkpoint`。
- **断点与幂等**：每个 Step 执行前检查 `GradeContext.checkpoint`（持久化在 `t_answer_sheet.mark_status` 即天然断点：0 答题中/1 待判分/2 客观已判/3 阅卷中/4 成绩已合成/5 已发布），重跑时跳过已完成 Stage；Step 内写操作均为 UPSERT 或条件更新，重复执行无副作用。
- **SUSPENDED 语义**：含主观题答卷执行到 `subjectiveScoreStep` 时若阅卷未完成 → 返回 SUSPENDED，上下文快照存 Redis `pipeline:ctx:grade:{sheetId}`；`MarkTaskAllDoneEvent` 触发 `PipelineEngine.resume("gradePipeline", sheetId)` 续跑。
- **失败兜底**：FAILED 答卷登记 Redis `pipeline:retry:grade`（ZSET，score=重试时刻），`GradeRetryJob` 每 5min 重跑（≤5 次，超限告警）；管理端支持人工触发重判。
- 纯客观卷在 `ExamSubmittedEvent` 同事务监听中同步跑完全部 4 Stage（成绩立即可见）；含主观题卷先同步跑完 Stage1~2 后挂起。

#### 3.5.2 九个 Step 逐一设计

**Step1 snapshotLoadStep（Stage1）**
- 输入：GradeContext{sheetId}。
- 处理：加载 `t_answer_sheet`（校验 mark_status ∈ {1}，否则 SKIPPED 防重跑）+ `t_answer_detail` 全量明细；解析 `paper_snapshot` 为 `PaperSnapshotDTO`（题目、分值、乱序映射、标准答案、blankConfig、multiJudgeRule、gradeRuleSnapshot）；构建 `detailId → 快照题目` 索引。
- 输出：context 填充 details / paperSnapshot / scoreMap（空）。
- 幂等：纯读操作，天然幂等。

**Step2 choiceJudgeStep（Stage1）**——单选/判断判分（FR-MARK-01）
- 输入：details 中 ques_type ∈ {SINGLE(1), JUDGE(3)} 且 mark_status=0 的行。
- 算法：考生 `user_answer.keys`（展示 key）经快照 `optionOrderMap` 还原为原始 key 集合 → 与标准答案 `answer.keys` 集合相等比较；相等 → score=ques_score、is_right=1；不等/未答 → score=0、is_right=0。
- 输出：scoreMap 更新；批量 `UPDATE t_answer_detail SET score, is_right, mark_status=1`；累计 objectiveScore。
- 幂等：以 `mark_status=0` 为执行条件，重跑跳过。

**Step3 multiChoiceStep（Stage1）**——多选三种判分规则
- 输入：ques_type=MULTI(2) 未判行；快照 `multiJudgeRule`。
- 算法：还原后的考生选项集 U、标准答案集 S：
  - `ALL_OR_NOTHING(1) 全对得分`：U==S → ques_score；否则 0；
  - `HALF_ON_MISS(2) 漏选得半分`：U==S → 满分；U⊂S（真子集，漏选且没错选）→ ques_score×0.5、is_right=2（半对）；含错选或未选 → 0；
  - `NONE_ON_MISS(3) 错选/漏选均不得分`：U==S → 满分；其余一律 0。
- 输出/幂等：同 Step2。

**Step4 blankMatchStep（Stage1）**——填空归一化匹配
- 输入：ques_type=FILL(4) 未判行；快照 `blank_config{ignoreCase, ignoreWidth, unordered}`。
- 算法：
  1. 归一化函数 `norm(s)`：trim →（ignoreWidth：全角→半角）→（ignoreCase：toLowerCase）→ 去除首尾标点空白；
  2. 逐空匹配：第 i 空考生答案 `norm(ub[i])` ∈ 该空可接受集合 `norm(blanks[i][*])` → 该空得分（空分值=ques_score/空数，保留 2 位小数，末空吸收舍入差）；
  3. `unordered=true`（多空乱序）：考生各空与标准空做二分图最大匹配（空数 ≤6，直接全排列匹配取最大命中数）；
  4. 整空得分汇总，全对 is_right=1、部分对 is_right=2、全错 0；
  5. **未命中疑似收集**：某空未命中但与标准答案相似度 `SimilarityUtils.jaccard ≥ mark.fill.similarity.threshold（默认 0.8）` → 记录 context.reviewQueue（不在本 Step 改状态）。
- 输出：scoreMap、明细更新 mark_status=1（命中判定者）。

**Step5 similarityCheckStep（Stage2）**——复核队列（FR-MARK-03）
- 输入：context.reviewQueue。
- 处理：将疑似明细 `UPDATE t_answer_detail SET mark_status=3（待人工复核）`，（该题 score 暂记 0 待复核结论覆盖）；无疑似则 SKIPPED。
- 输出：答卷若 reviewQueue 非空且含主观题 → 后续合成须等复核清空（复核由 MARK-05/06 人工完成，提交后重新触发 resume）。

**Step6 subjectiveScoreStep（Stage3）**——主观分合成
- 输入：ques_type=ESSAY(5) 明细 + `t_mark_task` 结果。
- 处理：
  - 检查本答卷全部主观题 MarkTask 是否完成（`mark_status ∈ {1已阅,3已仲裁}`）且复核队列无本答卷条目；未完成 → **SUSPENDED**（挂起等待 MarkTaskAllDoneEvent）；
  - 聚合：一评模式取 `round_no=1` 的 score；双评模式（`mark.double.enabled=true`）两轮均分（分差 ≤ mark.double.gapThreshold 取均值，超阈值时本不应出现——已生成 round_no=3 仲裁任务，取仲裁分）；
  - 回写明细 `score/mark_status=2（人工已判）`、is_right 按得分比例（满分=1，0 分=0，其余 2）。
- 输出：subjectiveScore。

**Step7 totalScoreStep（Stage3）**
- 处理：`totalScore = objectiveScore + subjectiveScore`（NUMERIC(6,2) 精度，BigDecimal 计算）；校验 `0 ≤ totalScore ≤ paperSnapshot.totalScore`，越界记 exceptionList 并 FAILED。
- 输出：totalScore；答卷 mark_status 3→4（成绩已合成）。

**Step8 levelEvalStep（Stage4）**——等级评定快照（FR-STAT-04）
- 输入：totalScore、paperSnapshot.gradeRuleSnapshot（规则条目副本：gradeCode/gradeName/min/max/开闭区间）。
- 算法：按 sort_no 遍历区间，`score ≥ min && (score < max || (upperInclusive && score == max))` 首个命中即等级；区间以快照为准，**不读 t_grade_rule 现值**。
- 输出：gradeCode/gradeName/grade_rule_id 写入 context；**不落库**（落库由 persistStep 统一做，保证"评定结果+规则快照"同一事务写入，FR-STAT-04）。

**Step9 persistStep（Stage4）**
- 处理（单事务）：
  ```sql
  UPDATE t_answer_sheet
     SET objective_score=?, subjective_score=?, total_score=?,
         grade_rule_id=?, grade_code=?, grade_name=?, mark_status=4
   WHERE id=? AND mark_status IN (1,2,3);   -- 条件更新保证幂等
  ```
- 发布 `GradeGradedEvent{sheetId, sessionId}`（成绩已合成；发布动作走 MARK-07 人工确认后置 mark_status=5）。
- 失败处理：事务回滚抛 FAILED → 重试队列。

#### 3.5.3 阅卷任务分配与提交（FR-MARK-02，MarkTaskService）

#### 3.6.3 分层级汇总下钻算法（STAT-02/03，FR-STAT-02）

**物化路径自底向上聚合**（statPipeline，GradePublishedEvent 触发 + StatSnapshotJob 兜底）：

```

  2. 一次 SQL 完成（GROUP BY 前缀分组，对应数据库设计 5.1 的 path 前缀思路）：
```

```
orgSummary(examId, orgId):           // STAT-02
  1. 数据权限：orgId 对应 path 须以 loginUser.orgPath 开头，否则 10004
  2. 优先读快照：SELECT * FROM t_stat_exam_unit
     WHERE session_id=? AND org_id IN (SELECT id FROM t_org_unit WHERE parent_id=:orgId AND deleted=0)
     （org_level=本级+1 等价过滤）→ children 列表
  3. 快照缺失（未发布/Job 未跑）→ 实时 SQL 兜底（数据库设计 5.1 原文）
  4. 同级排名 rank：children 内按 avgScore DESC（次键 passRate DESC）编号
  5. hasSubLevel = 存在子节点的子节点

orgDetail(detailType=USER):          // STAT-03 人员明细
  SELECT 考生行（t_exam_candidate JOIN t_answer_sheet）
  WHERE session_id=? AND org_path LIKE :orgPath||'%'（含下级，或仅本级按参数）
  rankInOrg：窗口函数 RANK() OVER (ORDER BY s.total_score DESC)
  （stat.rankPublic=false 仅影响考生端展示，管理端照常返回）
```

#### 3.6.4 t_stat_exam_unit 预聚合 Job 与导出

- **StatSnapshotJob**（每 30min，ShedLock）：扫描 `session_status=3`（已发布）但 `t_stat_exam_unit` 缺失或 `stat_time < 成绩最近变更时间` 的场次 → `rebuildSessionSnapshot`（重跑 statPipeline）；成绩复核改分后由业务代码直接调用重建。保证"统计结果与明细 100% 一致"验收口径可随时核对。
- **导出**（STAT-07）：`exportType=SUMMARY/DETAIL/QUESTION` 三种模板，EasyExcel 流式写临时文件 → FileStorage 预签名 URL（3600s）；数据权限过滤（orgPath 前缀）后导出；写操作日志。>5 万行转异步（生成任务记录，完成后站内通知下载，60002 兜底失败）。

## 6. 定时任务设计

| 任务名（类） | 触发 cron / 周期 | 职责 | 失败补偿 |
| --- | --- | --- | --- |
| SessionStatusJob | 每 1min | 场次到点自动流转（NOT_STARTED→IN_PROGRESS→ENDED）；ENDED 时触发未交卷强制收卷 | 任务幂等（条件 UPDATE）；异常下轮重扫；ShedLock 防多实例并发 |
| AutoSubmitJob | 每 15s | 扫描 `server_deadline<=now() AND submit_time IS NULL` 答卷自动交卷（submit_type=2） | submitInternal 幂等（WHERE submit_time IS NULL）；单份失败不影响其他，记 ERROR 日志下轮重试 |
| AnswerFlushJob | 每 5s | exam:dirty 队列批量 UPSERT 落库 t_answer_detail | 失败条目保留 ZSet 下轮重试；Redis 故障时降级直写 DB |
| AbsentMarkJob | 每 10min | 已结束场次标记缺考（candidate_status 0→2） | 条件更新幂等 |
| GradeRetryJob | 每 5min | 重跑判分失败答卷（pipeline:retry:grade，≤5 次） | 超限告警（t_sys_log + 监控）；支持人工后台触发重判 |
| LearnCompleteJudgeJob | 每 10min | 复核判定完成态（心跳中断前已达阈值的兜底） | 判定口径与 HeartBeatService 一致，幂等 UPDATE |
| LearnSessionCloseJob | 每 1min | 关闭过期学习会话，强制落库残留心跳数据 | 重入安全（DEL 后再处理） |
| QuesStatRefreshJob | 每日 02:00 | 按 t_answer_detail 聚合刷新题目 use/answer/right/right_rate | 全量重算幂等 |
| StatSnapshotJob | 每 30min | 已发布场次重建/补齐 t_stat_exam_unit | UPSERT 幂等；复核改分后由业务即时触发重建 |
| OrgPathCheckJob | 每日 03:00 | 全树 path/level 与父子关系校对修复 | 修复前后差异写 t_sys_log 告警 |
| UploadCleanJob | 每 1h | 清理 24h 未完成分片上传 | 清理前校验无进行中写入 |
| LogArchiveJob | 每月 1 日 04:00 | t_sys_log/t_sys_login_log 超 12 个月按月归档导出 | 归档文件校验行数后再删在线数据 |

全部任务 `@Scheduled` + `@SchedulerLock(name=...)`（ShedLock Redis 实现），锁时长 ≥ 预期执行时长；任务入口统一 try-catch 打 ERROR 日志（不接监控告警的静默失败禁止）。

- **倒计时组件**（CountdownTimer.vue）：进入时记录 `{deadlineEpoch, basePerfNow}`，渲染值 = `deadlineEpoch - (serverTimeAtEnter + (performance.now() - basePerfNow))`；禁止 `Date.now()` 绝对判断（防改系统时间）；每次 TAKE-05 响应与每 60s TAKE-03 校时重置基准；剩余 ≤5min（exam.remind.before.min）van-notice-bar 红色提醒；归零自动触发交卷（最终以服务端判定为准，本地只发起请求）。
- **答案本地缓存兜底与弱网重试**：
  1. 作答变更 3s 防抖聚合 + 30s 定时心跳兜底提交 TAKE-05（带 `clientBatchId` UUID）；
  2. 提交前快照写 `localStorage["exam:queue:{sheetId}"]`（待发送队列，不含任何答案/解析字段——只存考生作答）；
  3. 失败按 1s/3s/8s 指数退避重试，仍失败保留队列并 toast"答案已本地保存，恢复网络后自动同步"；`navigator.onLine`/`window.online` 事件恢复后按序重放（clientBatchId 保证服务端幂等）；
  4. 恢复/进页时 TAKE-08 对账：服务端 answers 为准合并本地未确认队列，合并后清空已确认项；
  5. 交卷必须在线完成：TAKE-07 失败持续重试直至成功或到点由服务端自动收卷（重试间隔 2s，页面阻塞式 loading）。
- **切屏检测**（useAntiCheat.ts）：监听 `document.visibilitychange`（hidden→LEAVE，visible→RETURN）与 `window.blur`（去抖 500ms，同一离开周期只报一次）调 TAKE-06；响应 `action=FORCE_SUBMIT` 或 TAKE-05 响应 `submitStatus≠IN_EXAM` → 清理 localStorage 队列并跳交卷完成页；`leaveCount/limit` 实时展示于答题页角标。
- **答题界面**（FR-TAKE-03）：题型分区锚点导航（TAKE-04 sections）、答题卡抽屉（已答/未答/标记三态徽标，点击定位）、上一题/下一题与交卷按钮固定底部拇指热区；单选 van-radio、多选 van-checkbox、判断 T/F 大按钮、填空逐空 input、简答 textarea（字数统计）。
- **学习页**：视频 van-video 自定义控件禁拖动超过已看最大点（防拖进度条刷进度，服务端仍有间隔校验兜底）；倍速播放按实际播放秒数上报 deltaSec；`visibilitychange` hidden 即暂停并停发心跳。
- **脱敏红线**：考生端不持久化任何含标准答案/解析的数据；成绩解析仅 TAKE-09 发布后按 `showAnalysis` 渲染。

### 8.2 考试脱敏实现（DTO 裁剪，NFR-04）

`PaperSnapshotService.toClientVO(snapshot, sheetId)` 为考生端唯一出卷通道，裁剪规则（白名单序列化，`@JsonView(AppView.class)` 强制）：

| 快照字段 | 考生端 TAKE-04 | 成绩发布后 TAKE-09（showAnalysis=true） | 管理端 PAPER-03/07 |
| --- | --- | --- | --- |
| stem / options(content) | ✅ | ✅ | ✅ |
| answer / isAnswer / blanks 答案 | ❌ | ✅（correctAnswer） | ✅ |
| analysis / points / reference | ❌ | ✅（showAnalysis 控制） | ✅ |
| optionOrderMap / 原始 quesId | ❌（仅 sheetQuesId=detailId） | ❌ | ✅ |
| total_score / grade_* | ❌（交卷前） | ✅（mark_status=5 后） | ✅ |

实现要点：客户端 VO（`AppQuestionVO`）为独立类不含敏感字段（而非字段置空），从结构上杜绝泄漏；`sheetQuesId` 使用 `t_answer_detail.id`，不下发题库 itemId 防反推；富文本内图片经签名 URL 下发。

### 8.4 与输入文档的口径裁决说明

详细设计遵循以下裁决（不影响输入文档原文，仅实现口径）：

1. 试卷快照以 `t_paper_question` + `t_answer_sheet.paper_snapshot` 为准（数据库设计），概要设计中的 `t_paper_snapshot` 表述视为同一机制的早期命名。
2. 错误码、枚举字符串编码、接口路径（`/api/v1/app/**`）以 API 设计为准；概要设计 6.1 的 `/take/**` 前缀与 1xxx~5xxx 错误码段视为早期表述。
3. 系统参数键名以 API 设计 4.13（`learn.heartbeatSec`、`exam.switchScreenLimit` 等）为准；数据库设计 7.4 初始化脚本的键名（`learn.heartbeat.interval` 等）需在实施时统一为前者。
4. 场次 CANCELED 状态：API 设计含 CANCELED，数据库 `ck_session_status CHECK (0..3)` 未含取消值，实施时扩展取值 4=CANCELED 并同步放宽 CHECK 约束。
