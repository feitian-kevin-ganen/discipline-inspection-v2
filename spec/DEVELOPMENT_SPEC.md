# 在线考试系统开发规约

> 适用范围：`/home/cloud/projects/AIExamK3`（纪检监察人员在线考试培训系统）  
> 生效范围：所有代码、脚本、配置、SQL 的修改与提交。

## 1. 交付物三段式

- 严格按指令指定的名称和路径落盘。
- 指令未指定的，**先问再写**，不得擅自新建文档或目录。
- 交付结果必须能直接对应到指令中的目标路径与目标文件名。

## 2. 核对清单

- 范围超过 **3 个功能点** 的任务，完成后必须输出逐项核对表。
- 核对表格式：

| 功能点 | 状态 | 验证方式 |
|--------|------|----------|
| 示例功能 | 完成/未完成 | 单元测试 / 接口调用 / 无头浏览器截图 |

- 未完成项必须**如实标注**，禁止隐瞒部分实现或虚报完成。

## 3. 全量冒烟

- 凡改动**菜单、路由、权限、公共组件、登录鉴权**，完成后必须**全量遍历受影响面**。
- 遍历优先使用脚本（如无头浏览器、接口遍历、curl 批量探测）。
- 必须输出**问题清单**；问题清单必须为零，才算完成。
- 抽查通过不算完成。

## 4. 权限同步

- 新增菜单/按钮的同时，必须生成对应的**授权 SQL**。
- 新页面调用系统级接口（选人、选部门、字典、组织树等）时，必须检查**全部业务角色权限**，缺一项补一项。
- 禁止出现“页面能打开但角色无权限调用接口”的情况。

## 5. 字段契约

- 新增/修改表字段时，必须核对设计文档中的**字段级契约表**。
- 前后端必填校验责任按契约执行：
  - 后端非空字段必须有兜底校验；
  - 明确由前端保证的字段，必须在接口文档或契约中注明。
- 禁止出现前后端校验不一致导致数据库报错的情况。

## 6. Bug 修复流程

- **先讲根因，再改代码。**
- 改完后必须按**复现路径实测**验证：
  - 优先使用无头浏览器或 curl；
  - 必须给出证据：截图、接口返回摘要、日志片段等。
- 只改代码不做实测验证，不算修复完成。
- 修复一个 bug 时，必须**同类页面、同类接口一并排查**，防止同类问题遗漏。

## 7. SQL 与代码同提交

- Git 提交时，**代码与对应 SQL 脚本必须一起提交**。
- 提交日志采用**中文 conventional 格式**：

```text
<类型>(<范围>): <要点>
```

常用类型：`feat`（新功能）、`fix`（修复）、`chore`（构建/配置）、`docs`（文档）、`refactor`（重构）、`perf`（性能）。

示例：

```text
fix(考试): 修复交卷后仍可访问答题页的空壳问题
feat(学习): 新增学习进度 read_pages 字段及落库逻辑
chore(数据库): 新增通知批次号字段及回填脚本
```

## 8. 不发明需求

- 需求文档中引用了但**全文找不到定义**的规则、矩阵、字典、枚举值等，必须列入**“需客户澄清”清单**。
- 不得自行编造内容、默认值或业务规则来填补空白。
- 与客户确认后，将确认结果补充到需求或设计文档中。

## 9. 环境边界

- **不得 kill 非本项目进程。**
- **不得修改其他项目的目录、配置、中间件。**
- 后端重启只允许重启**本项目进程**。
- 使用公共中间件（数据库、Redis、MinIO 等）时，必须先确认是否影响其他项目。

## 10. 并发保护

- 未获明确许可，不得在同一构建目录**并行执行多个构建**。
- 不得同时运行多个**写库脚本**。
- 多人/多任务共用环境时，必须排队或申请独立资源。

## 附：每次修改代码前自检

提交代码前，请确认：

- [ ] 交付路径和名称与指令一致；
- [ ] 功能点超过 3 个时已输出核对清单；
- [ ] 涉及菜单/路由/权限/公共组件/登录鉴权时已全量冒烟；
- [ ] 新增菜单/按钮时已生成授权 SQL；
- [ ] 新增/修改字段时已核对契约表；
- [ ] Bug 修复已实测并保留证据；
- [ ] 相关 SQL 已随代码一起提交；
- [ ] 提交日志符合中文 conventional 格式；
- [ ] 未自行编造未定义的需求；
- [ ] 未影响其他项目进程或配置；
- [ ] 未在构建/写库环节造成并发冲突。
